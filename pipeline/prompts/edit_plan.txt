Some instructions describe a creative feeling or intent rather than naming a specific field —
e.g. "make this more dramatic," "make this pop more," "tone this down," "make this feel
calmer." The creator should not need to know field names to get a reasonable change. For an
instruction like this:

- Translate the feeling into the single most plausible change among that scene type's editable
  fields listed below — do not invent fields that don't exist (there is no "template" or
  "emphasis style" field today, even though a request like this might suggest one; "entrance" IS
  a real field, but ONLY for "moment" scenes with treatment "bottom-callout" — see the dedicated
  entrance guidance below for when to use it instead of a generic field guess). For example, on
  a "moment" scene, "make this more dramatic" might reasonably become a longer durationInFrames
  (it lingers longer, reads as more weighty) and/or a punchier text/caption rewrite — grounded in
  what is actually said in the parent scene (quote closely, paraphrase minimally, never invent
  content that wasn't said, same discipline as the moment creation rule above), not a generic
  dramatic-sounding phrase unrelated to the actual content.
- Prefer ONE well-chosen field change over touching every field you're allowed to. A vague
  instruction is asking for a single meaningful nudge, not a rewrite of the scene.
- If the selected/targeted scene type's editable fields genuinely offer no plausible way to
  express the requested feeling (e.g. "make this more dramatic" against a scene type whose only
  editable fields are timing, with no text content to intensify), it's fine to still make a
  small, defensible timing change (e.g. lengthen duration slightly) rather than defaulting to an
  empty operations list — only return no operations if you cannot identify which scene the
  instruction even refers to (see the ambiguity guidance below), not merely because the
  requested feeling has no perfect field to express it in today.

Some instructions ask specifically about how an element ENTERS the frame — e.g. "make this fade
in," "make this pop/scale in," "give this a more dramatic entrance," "make this slide up." A
"moment" scene with treatment "bottom-callout" supports a real, configurable "entrance" field
with exactly three values:
- "fade" — a plain opacity fade, no motion. Use for "fade in," "make this calmer/less busy,"
  "tone down the entrance."
- "scale" — a spring-driven scale-up (this is also the default when entrance is omitted, so a
  request that just means "the current/normal entrance" doesn't need this operation at all).
  Use for "pop in," "scale in," or a generic "make the entrance more dramatic/energetic" request.
- "slide" — a spring-driven slide up from below. Use for "slide in," "slide up," or when the
  instruction asks for motion specifically (not just a mood).
Only propose an entrance update for a "moment" scene whose treatment is "bottom-callout" — other
treatments/scene types have no configurable entrance, so a request like this against one of
those has no field to express it in (fall back to the general vague-instruction guidance above,
or return no operations if genuinely nothing fits). Do not invent a fourth entrance value — pick
the closest of the three.
